# V2.6.1 — bow and hands checkpoint

Preview: `prototypes/v2.6.1-bow-study.html`. Comparison: `docs/v2.6.1/comparison.html`.
This is a separate local file. V2.6, the environment, enemies and gameplay code
are preserved. No push or deployment.

## Asset work

- New carved wooden riser with an arrow shelf, narrower laminated limbs,
  tip overlays, leather grip winding and one 256 px colour-grain texture.
- Distinct left grip and right three-finger hook, with glove heel/knuckle
  planes, individual finger segments, thumb, stitched panels and wrist bands.
- Forearms use changing elliptical sections, taper and shallow tendon planes.
  Rolled sleeves and fold ridges break up the previous uniform bare cylinders.
- Arrow includes a shaft, head, three feather vanes and split nock. The nock
  stays attached to the string midpoint in ready, half and full draw.
- The draw hand faces the string correctly and follows through on release.
  Bow deformation edits existing vertex buffers. Static details are batched.

The result remains visibly faceted. It is a proportion/geometry improvement,
not a claim of matching the concept's finished painted hands and material detail.

## Validation

Eight focused checks passed in Chrome: string/nock attachment at three poses,
arrow visibility on release, actual fire-button draw and launch, projectile
hits at three distances, stable geometry/texture counts during repeated posing,
and portrait layout. No browser errors. Four exported GLBs were independently
loaded and rendered. `test-results.json` records results. Existing movement,
waves, pickups, health and restart implementations are unchanged; the full
V2.6 suite is documented in the prior review, not claimed as newly rerun here.

Screenshots: ready, half, draw, release and phone-draw. The comparison page
shows actual V2.6 and V2.6.1 captures, plus the independent asset renders.

Four separate GLBs and a manifest are in `assets/v2.6.1-bow/`:
732-triangle bow, 1,226-triangle grip arm, 1,148-triangle draw arm and
82-triangle arrow. Every GLB is below 160 KiB. These are static ready-pose
exports, not skeleton-rigged arms or baked animation. Code drives the
foreground motion. JSON `sourceOffset` restores runtime coordinates from
the base-centred exports; the game applies a separate viewmodel scale.

## Rebuild

1. `python tools/build_v261_bow.py`
2. `node tools/review_v261_bow.cjs`
3. `python tools/export_v261_bow.py`
4. `node tools/preview_v25_assets.cjs assets/v2.6.1-bow front`

The export input `asset-geometry.json` is browser-captured geometry; it can be
regenerated by step 2. The new builder replaces the exact V2.6 weapon source
only and fails if that source no longer matches the preserved preview.

Stop here for visual review before changing another part of the game.
